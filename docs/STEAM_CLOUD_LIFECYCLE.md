# Steam 启动与云存档生命周期修复（2026-10-06）

## 行为

- Wine 字体注册和显示配置超时后，清理 Bottle 残留进程并重试一次；再次失败显示具体操作和诊断路径。非超时错误不自动重试。
- 诊断文件：Steam Bottle 下 `.indie-diagnostics/wine-preparation.log`。
- 首页依据 Windows Steam 的实际连接和 `logs/cloud_log.txt` 显示状态，客户端在线不再等同于云存档同步完成。
- 观察到游戏运行时持久化 AppID、账户和开始时间；只有同账户、本次运行之后的完整退出上传确认才能清除待上传记录。
- 切换会导致 Steam 重启的显示/运行环境设置，以及退出应用时，检查游戏进程并等待云同步，最多 60 秒。
- 同步未确认时保留 Steam。应用退出提示可以取消退出继续等待，或者仅退出应用、保留 Steam。正常退出请求使用 Steam `-shutdown`，不再强杀客户端。

## 数据与边界

上传仍由 Steam 官方客户端负责。项目只读取日志，不直接写存档、`remotecache.vdf` 或模拟上传成功。

日志解析只读取末尾 2 MB，忽略残缺行和 Steam 自身 AppID 7。账户切换、上传失败、新上传批次会清除旧上传证据；文件上传成功、下载成功、缓存评估完成不能替代整批退出上传确认。

游戏不支持云存档、云存档被禁用、日志轮转、未知日志格式或缺少账户信息时，可能无法确认上传。此时保守保留 Steam；这不是启用该游戏云存档的能力。跨设备最终存档一致性还需要在另一台设备验证。
