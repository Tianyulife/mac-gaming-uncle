# 《双影奇境》空间音频实验验收

测试由用户执行，输出设备使用 macOS 当前默认设备。尚未确认游戏是否调用 Windows Spatial Audio API，也未宣称游戏兼容或实际空间效果已通过。

## 实验包安装

1. 使用本轮构建的 `dist/Mac Gaming Uncle.app`。
2. 解压 `dist/runtime/indie-wine-11.0.3-spatial.2-macos-x86_64.tar.xz`，在应用“运行时 → 导入本地 Wine”选择 `wine-runtime` 文件夹。仓库已有解压目录 `dist/runtime/extracted/wine-runtime`。
3. 在运行时列表确认 **11.0.3-spatial.2** 已导入。导入器保留游戏引擎身份和实验版本，游戏流程会选择已安装的较新游戏引擎。
4. 完全退出游戏及应用托管的 Windows Steam，再重开应用和 Steam，使旧 Wine 进程退出并重新加载新引擎。保留原有图形配置；若应用要求 D3DMetal，请先完成 GPTK 导入。

如果首次启动还未完成环境设置，也可以先用仓库 CLI 导入：

```sh
.build/release/macgamingunclectl wine local-install dist/runtime/extracted/wine-runtime
```

原有运行时目录和游戏数据保留；需要回退时，退出游戏和 Windows Steam，将实验版本移出运行时目录并重开应用。应用默认下载制品仍为 11.0.2。

## 第一步：阻断空间音频客户端激活

诊断版本 11.0.4-probeoff.1 以原 spatial.2 为基底，只改变双架构 mmdevapi.dll，在 SpatialAudioClient_Create 返回 E_NOINTERFACE（输出指针为 NULL），并写入固定 MGU_DIAGNOSTIC 标记。其余新音频实现、CoreAudio、图形层与原实验包一致。32/64 位独立探针验证 HRESULT=0x80004002，普通混音查询仍为 8 声道/48 kHz，设备周期 106667 个 100 ns 单位。已导入并发起真实游戏测试，游戏结果和是否实际请求该接口待观察。该诊断版本不用于发布。证据位于 work/full-runtime/spatial-probe-gate。

诊断启动已确认加载 11.0.4-probeoff.1；游戏启动日志 242AECA5-6F26-4902-9EDC-D5C73DFACC4E-steam-d3dmetal.log 出现 SpatialAudioClient 激活阻断标记。已请求用户在同一场景报告画面及声音。能力探测确有发生，但是否导致卡顿仍需此次结果。
